# [订单列表] PRD

## 一、User Story
> 作为门店店长，我希望查看本店全部团员订单，按团员订单状态筛选、按活动或客户信息搜索，以便跟进团员订单的支付、核销、退款等处理情况。

---

## 二、Function Requirements

### F0 全局口径
- **功能描述**：统一约定全项目的团与订单归属、B/C 两端订单状态映射、未支付订单有效期。本模块为以上规则在全项目的唯一出处，其余文件一律引用，不重复定义。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. **团**：团是团员订单的聚合结果，不独立保存，不承载时间、客户、留言等附加信息，也不存在团状态；团对外呈现团名称、活动名称、分享人手机号、团金额四项聚合信息，另附溯源字段「推荐门店」（以团员订单为维度记录与展示，仅在推荐门店与承接门店不同时展示，口径见规则 13），不呈现团号，展示位置以各页面模块规定为准。门店侧展示的手机号（分享人手机号、客户手机号）一律明文，不做脱敏；本句为门店侧手机号展示口径的唯一出处。
  2. **聚合维度**：团按「分享人 + 活动」聚合，一个分享人在一个活动下对应一个团，跨活动的订单不合并；无团订单的聚合维度见规则 9。
  3. **团名称**：取分享人姓名，展示为「分享人姓名＋的团」（如「张女士的团」）。本规则为团名称的唯一口径。
  4. **订单归属（归因）**：每笔团员订单归属其下单人的上级分享人在本活动下的团；上级分享人指引导该下单人进入活动的分享人。归因的唯一凭证为会员通过「分享邀请好友参团」生成的分享链接，有效分享渠道见《活动详情 PRD》F6 规则 8；商家直接分享、平台或门店二维码扫码、未经分享进入活动等无归因渠道产生的订单，不属于任何团。归因与成团均以活动配置了「老带新」玩法为前提（见规则 12）。本规则为订单归因的唯一口径。
  5. **分享人本人订单（自购）**：分享人经本人分享链接进入活动下单时，本人订单归入本人的团，计入本人团的成团进度；经他人分享链接进入时，归入上级分享人的团；经无归因渠道进入时，本人订单不属于任何团。本规则为分享人本人订单归属的唯一口径。
  6. **多级分享**：被分享人可继续分享，各分享人对应的团相互独立、互不合并。
  7. **订单与团的关系**：一次下单生成一条团员订单，同一被分享人在同一活动下的多次下单归入同一个团；分享人本人可不下单，不下单不影响其团的聚合。
  8. **团金额**：为团内全部**未被逻辑删除**的团员订单金额（各订单创建时的金额）的合计快照，不因订单后续处理、状态筛选或搜索而变化；未支付超时被逻辑删除（关闭）的团员订单不计入（见规则 11）。
  9. **无团订单**：不属于任何团的订单，即**未经归因渠道产生的订单**——包括商家直接分享、平台或门店二维码扫码、未经分享进入活动等渠道；全部无团订单以活动为维度聚合：同一活动下的全部无团订单聚合为一张卡片，卡片名称统一为固定名称「商家直接分享的订单」并标注该活动名称；该卡片无分享人、不适用团命名规则，金额为卡内全部订单金额合计（口径同规则 8）。本规则为无团订单的聚合口径与展示形态的唯一出处；未配置「老带新」玩法的活动订单必然无归因，其归属见规则 12。
  10. **B/C 两端订单状态映射**：

      | 门店侧（B 端） | 会员侧（C 端） |
      | --- | --- |
      | 待支付 | 待支付 |
      | 待核销 | 已支付 |
      | 已核销 | 已使用 |
      | 已退款 | 已退单 |

      「已核销」指该团员订单的服务项目份数已全部核销完成；未全部核销（含部分核销）一律记为「待核销」。核销的份数口径与操作见《订单详情（门店侧） PRD》F9。
  11. **未支付有效期**：未支付团员订单自创建起 1 小时内有效；超时由系统自动逻辑删除（关闭），不支持手动关闭。逻辑删除后，门店侧与会员侧均不再出现在任何列表、筛选与搜索结果中，双方均无法进入该团员订单详情。
  12. **成团前提**：团仅在配置了「老带新」玩法的活动下产生。未配置「老带新」玩法的活动不产生分享入口，其订单无法经分享进入、必然无归因，一律归入「商家直接分享的订单」（见规则 9）。玩法定义见《活动配置 PRD》F4。
  13. **订单推荐门店（溯源）**：每笔团员订单记录其「推荐门店」（推荐该订单客户进入活动的门店），供后续服务门店溯源。推荐门店由该订单客户**进入活动时所经链接携带的门店参数**确定——客户通过哪家门店的分享链接进入活动，即记为哪家门店。**推荐门店仅在「推荐门店 ≠ 承接门店」时记录与展示**：客户经门店分享链接进入活动时，若该分享门店即活动所属门店（承接门店），属门店分享自有活动、客户自助下单，不视为跨店推荐，不记录、不展示推荐门店；仅当分享门店与承接门店不是同一家门店（跨店推荐）时，才记录并向承接门店展示推荐门店；承接门店为活动所属门店（承接该活动的门店），与推荐门店含义不同。推荐门店以**团员订单为维度**记录并展示：订单列表卡片与订单详情均按团员订单逐条展示其推荐门店，不按团收敛；同一团内不同订单的推荐门店可不同（不同团员分别经不同门店的链接进入同一活动），**团不因推荐门店不同而拆分**，仍按「分享人 + 活动」聚合（见规则 2），以各订单自身记录的推荐门店为准（订单列表卡片字段见 F3 规则 1，订单详情展示见《订单详情（门店侧） PRD》F3）。推荐门店的归因与统计以订单创建时间为准：记录订单创建时该订单的推荐门店，不随后续订单状态变化而改变；订单不论状态（待支付、待核销、已核销、已退款）均计入推荐门店的推荐统计，但已被逻辑删除（超时关闭）的团员订单不计入（见规则 11）。无推荐来源的订单（即「商家直接分享的订单」，见规则 9）不记录、不展示推荐门店。

### F1 订单搜索
- **功能描述**：页面顶部提供搜索框，支持多字段模糊搜索团员订单；命中任一团员订单时，其所属的团整体进入结果。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 搜索字段为活动名称、客户姓名、客户手机号、团员订单号、分享人姓名、分享人手机号，均为模糊匹配。
  2. 搜索与状态筛选取交集：在当前筛选结果内匹配，任一条团员订单命中即带出其所属的团，卡片内仅展示命中且符合当前筛选条件的团员订单明细。
  3. 无团订单同样参与搜索，命中后归入其所属活动对应的「商家直接分享的订单」卡片（见 F0 规则 9）；该卡片无分享人，不参与分享人姓名、分享人手机号字段的匹配。
  4. 未找到匹配的团时，展示「未找到匹配的订单」。

### F2 订单状态筛选
- **功能描述**：页面提供「全部、待支付、待核销、已核销、已退款」五个状态标签，用于筛选团员订单，团本身不被剔除。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 「全部」：展示所有团，每个团带出其下全部团员订单明细。
  2. 其余四个状态：展示至少包含一条该状态团员订单的团，卡片仅带出该状态的团员订单明细。
  3. 状态筛选与搜索可组合使用，结果为两者交集。
  4. 已超时逻辑删除的团员订单不参与全部状态的筛选与展示（见 F0 规则 11）。
  5. 未输入搜索关键词时，当前状态筛选下无任何团员订单，展示「暂无符合条件的订单」；已输入搜索关键词时，按 F1 规则 4 展示「未找到匹配的订单」。

### F3 团列表
- **功能描述**：以卡片形式展示团列表，每张卡片为一个团；卡片展示团名称、活动名称、分享人手机号、团金额，并直接披露该团的团员订单明细。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. **卡片字段**：团名称、活动名称、分享人手机号、团金额，以及团内每条团员订单的团员订单号、客户姓名、客户手机号、下单时间、金额、状态、推荐门店（仅跨店推荐时展示，口径见 F0 规则 13）、未答复留言标记。本规则为订单列表卡片呈现字段的唯一口径。
  2. 活动名称取自该团内任一团员订单（团已按活动聚合，团内活动唯一）。
  3. 分享人手机号在列表卡片与订单详情页均展示，明文口径见 F0 规则 1；分享人姓名已体现在团名称中（见 F0 规则 3），卡片不重复展示。
  4. 门店侧不展示团号，团以团名称标识（见 F0 规则 1）。
  5. 团员订单明细的展示范围随 F2 筛选联动；团员订单的处理操作见《订单详情（门店侧） PRD》，本模块不展开。
  6. 未答复留言标记以团员订单为维度判定，判定标准见《订单详情（门店侧） PRD》F4。
  7. 「商家直接分享的订单」卡片按 F0 规则 9 展示，无分享人手机号与推荐门店；每张卡片仅含单一活动，卡片上标注该活动名称，明细行不重复标注活动。
  8. **明细条数上限**：每张卡片默认最多展示 3 条团员订单明细。明细表头展示团员订单条数（「团员订单明细 · 共 N 条」，N 为当前筛选下该团的团员订单条数），表头右侧提供「查看详情」入口。
  9. 团金额不因明细条数上限而改变（见 F0 规则 8）；该团全部团员订单在订单详情页查看（见《订单详情（门店侧） PRD》F3）。
