## 二、改动明细

### 01 分项目核销（B 端）

门店侧订单详情由整单核销改为**按服务项目/商品逐份核销**，核销入口、状态判定、退款与技术服务费口径随之调整。

1. **核销入口**：仅对「待核销」状态的团员订单展示；「待支付」「已核销」「已退款」不可核销。
2. **逐份核销**：按服务项目/商品逐项按份选择，每项可选范围 0 至该项剩余未核销份数，可跨多个项目同时选择，各项累计须大于 0 份；支持分次核销。
3. **剩余份数**：每项剩余未核销份数 = 该项份数 − 该项累计已核销份数；已核销份数以团员订单为维度累计保存。
4. **二次确认**：确认框展示客户姓名、本次核销份数，并提示「请确认客户已到店」；取消则不做任何改动。
5. **状态流转**：该订单全部服务项目/商品份数核销完成时，状态变更为「已核销」并进入核销成功页；未全部核销时状态保持「待核销」，剩余份数可再次核销。
6. **状态判定**：「已核销」指该团员订单服务项目份数**全部核销完成**；未全部核销（含部分核销）一律记为「待核销」；「待核销」含从未核销与部分核销两种情形。
7. **逐项核销进度**：「待核销」展示「已核销 X/Y 份 · 剩余 Z 份」；「已核销」展示「已核销 Y/Y 份」；「待支付」「已退款」仅展示份数（「×Y」）。
8. **退款条件**：退款仅对「待核销」**且从未核销（累计已核销份数为 0）**的团员订单可用；已发生部分核销、已全部核销后均不再提供退款入口。
9. **退款金额**：为该团员订单金额（**全额**），不按已核销/未核销部分拆分；退款后状态变更为「已退款」，不可再核销。
10. **技术服务费与净收入**：设该团员订单金额为 X 元；X ≥ 20 时技术服务费 = 5 元、门店净收入 = X − 5；X < 20 时技术服务费 = 0 元、门店净收入 = X。
11. **扣费时点**：技术服务费于该订单**全部核销完成、状态转「已核销」时**从其订单金额中一次性扣除，全部由门店承担、核销后不退还；部分核销阶段（仍为「待核销」）不单独扣费。
12. **结算**：核销成功后其净收入才计入结算流水、成为可提现的拓客收入；核销前不入流水、不可提款。

- **口径出处**：《订单详情（门店侧）PRD》F3 规则 6 / F5 / F6 / F8 / F9。
- **涉及**：`b008_order_detail.html`、`b008_order_detail.md`

### 02 推荐门店溯源

团员订单新增溯源字段「推荐门店」，以团员订单为维度记录与展示，可溯源该订单客户由哪个门店推荐进入活动。

1. **展示内容**：展示推荐该订单客户进入活动的门店名称，供当前服务门店溯源。
2. **门店来源**：推荐门店由客户**进入活动时所经链接携带的门店参数**确定——客户通过哪家门店的分享链接进入活动，即记为哪家门店。
3. **展示条件**：**仅当推荐门店与承接门店不是同一家门店（跨店推荐）时记录与展示**；门店分享自有活动、客户自助下单（推荐门店 = 承接门店）不视为跨店推荐，不记录、不展示推荐门店。
4. **记录与展示维度**：以**团员订单为维度**记录并展示；订单列表卡片与订单详情均按订单逐条展示其推荐门店，不按团收敛，以各订单自身记录的推荐门店为准。
5. **同团可不同店**：同一团内不同订单的推荐门店可不同（不同团员分别经不同门店的链接进入同一活动）；**团不因推荐门店不同而拆分**，仍按「分享人 + 活动」聚合。
6. **归因时点**：以订单创建时间为准，记录订单创建时该订单的推荐门店，不随后续订单状态变化而改变；订单不论状态（待支付、待核销、已核销、已退款）均计入推荐统计，**但已被逻辑删除（超时关闭）的团员订单不计入**（见《订单列表 PRD》F0 规则 11）。
7. **无归因订单**：「商家直接分享的订单」卡片不记录、不展示推荐门店；由该卡片进入订单详情时，团名称固定展示为「商家直接分享的订单」，不展示分享人与推荐门店。
8. **与承接门店区分**：「承接门店」为活动所属门店（承接该活动的门店），「推荐门店」为推荐来源门店，二者含义不同；推荐门店是否展示即取决于其与承接门店是否一致。

- **口径出处**：《订单列表 PRD》F0 规则 13、F3 规则 1；《订单详情（门店侧）PRD》F1 规则 2、F3 规则 1。
- **涉及**：`b007_order_list.html / .md`、`b008_order_detail.html / .md`

### 03 推荐下单跟踪（我的推荐）

《剑琅获客》首页新增「我的推荐」列表，推荐门店可跟踪经其推荐产生的团员订单。

1. **位置**：首页「本月数据」之后；仅列表、不提供详情页。
2. **字段**：被推荐客户姓名、订单状态、活动名称、承接门店、下单时间。
3. **范围**：仅收录经本店推荐后**已创建**的团员订单；推荐后未产生订单的客户不出现（列表有记录即代表已下单）；已被逻辑删除（超时关闭）的订单不计入。
4. **状态**：取值为「待支付」「待核销」「已核销」「已退款」，订单不论状态均展示（已被逻辑删除的订单除外）。
5. **排序**：仅按下单时间由近及远，订单不论状态均计入排序。
6. **展示量**：完整展示本店全部推荐订单，不设条数上限、不提供「查看全部」入口；无推荐订单时展示空状态。

- **口径出处**：《剑琅获客 PRD》F4。
- **涉及**：`b001_home.html`、`b001_home.md`

### 04 客户自动入会

《剑琅获客》门店信息区新增客户入会与统计时点描述，并明确客户统计与会员新增为两条相互独立的逻辑。

1. **同源触发**：客户在本店活动下的团员订单**支付成功后**，客户统计与会员新增两件事分别发生；两者由同一个「支付成功」事件各自触发，彼此独立、互不依赖、互不阻断。
2. **逻辑一 · 客户统计（新增客户）**：以支付成功的团员订单为准，门店维度、按手机号去重，页面加载时刷新；客户手机号在本店**首次成交**时「本月新增客户」「累计客户」各加 1，同一手机号重复成交不重复计数；未支付（待支付）及已被逻辑删除的订单不计入。
3. **逻辑二 · 会员新增**：客户在本店活动下的团员订单支付成功后，若其在【RTB】会员体系中尚不存在（以手机号为准），则新增一条本店会员客户数据；已存在的会员不重复新增。
4. **范围**：会员列表本身不在本模块范围，由会员相关模块承接。

- **口径出处**：《剑琅获客 PRD》F1 规则 3、规则 4、规则 5。
- **涉及**：`b001_home.md`

### 05 两端术语口径统一

门店侧与会员侧状态名称一一对应，两端术语各自使用、不混用。

| 门店侧（B 端） | 会员侧（C 端） |
| --- | --- |
| 待支付 | 待支付 |
| 待核销 | 已支付 |
| 已核销 | 已使用 |
| 已退款 | 已退单 |

1. **术语不混用**：门店侧状态用「已退款」，不写会员侧用语「退单」；会员侧消费动作称「使用」，不写门店侧用语「核销」。
2. **对应关系**：会员侧「已使用」对应门店侧「已核销」；已使用份数口径见《订单详情（门店侧）PRD》F9。

- **口径出处**：《订单列表 PRD》F0 规则 10；《剑琅获客 PRD》F1；《订单详情（会员侧）PRD》F1 / F2 / F6；《活动详情 PRD》F5 / F7；《我的订单 PRD》F2 / F3。
- **涉及**：`b007_order_list.md`、`b001_home.html / .md`、`c008_order_detail.html / .md`、`c019_insider_detail.html / .md`、`c022_my_orders.html / .md`

### 06 C 端使用情况去分母

《我的订单》《订单详情（会员侧）》的使用进度展示统一去分母，只保留已使用份数。

1. **订单详情 · 服务内容标题**：由「已使用 x/y 份」改为「已使用 x 份」（x 为各项目已使用份数之和，不展示总份数；x 为 0 时同样展示「已使用 0 份」）。
2. **订单详情 · 单项使用情况标签**：由「未使用 / 已使用 / 部分已使用 X/Y 份」改为「未使用 / 已使用 X 份」，部分使用与全部使用共用「已使用 X 份」文案。
3. **我的订单 · 活动说明**：由「已使用 x/y 份」改为「已使用 x 份」（x 为 0 时同样展示「已使用 0 份」）。

- **口径出处**：《订单详情（会员侧）PRD》F2；《我的订单 PRD》F3。
- **涉及**：`c008_order_detail.html / .md`、`c022_my_orders.html / .md`
