# [订单详情（门店侧）] PRD

## 一、User Story
> 作为门店店长，我希望查看团的金额、团员订单明细及客户留言，并对团员订单的服务项目/商品逐份核销、退款、联系客户等操作，以便完成订单履约。

---

## 二、Function Requirements

### F0 门店侧操作二次确认
- **功能描述**：门店侧对核销、退款、奖励发放三项不可逆操作均要求二次确认后执行。本模块为门店侧二次确认的唯一口径。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 点击核销、退款、奖励发放入口时，先弹出确认框；门店确认后执行操作，取消则不改变任何状态。
  2. 三个确认框的展示内容与执行结果分别见 F5（退款）、F9（核销）、F7（奖励发放），本模块不重复定义。

### F1 团信息
- **功能描述**：页面顶部展示团的聚合信息：团名称、活动名称、分享人、团金额。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 团名称、活动名称、团金额、聚合口径、团不承载状态的规则及门店侧手机号明文展示口径，均见《订单列表 PRD》F0，本模块不重复定义。
  2. **推荐门店（溯源）**：以**团员订单为维度**逐个展示该订单的推荐来源门店（推荐该订单客户进入活动的门店）名称，供当前服务门店溯源，展示位置见 F3 规则 1。推荐门店由该订单客户**进入活动时所经链接携带的门店参数**确定；**仅当推荐门店与承接门店（活动所属门店）不是同一家门店、即跨店推荐时才展示**，门店分享自有活动、客户自助下单（推荐门店 = 承接门店）不展示。同一团内不同订单的推荐门店可不同（不同团员分别经不同门店的链接进入同一活动），**团不因推荐门店不同而拆分**，以各订单自身记录的推荐门店为准。无推荐来源的订单（「商家直接分享的订单」）不展示推荐门店；归因口径见《订单列表 PRD》F0 规则 13。
  3. 分享人展示其姓名与手机号（明文，见《订单列表 PRD》F0 规则 1）；团员订单明细中的客户姓名为该订单的下单人，二者可能为不同的人：分享人本人经他人分享链接下单时，其订单的客户姓名为分享人本人，该订单归入上级分享人的团；经本人分享链接自购时，归入本人的团（归属规则见《订单列表 PRD》F0 规则 4、规则 5）。
  4. 门店侧不展示团号，团以团名称标识（见《订单列表 PRD》F0 规则 1）。
  5. 由「商家直接分享的订单」卡片进入本页时，团名称固定展示为「商家直接分享的订单」，不展示分享人与推荐门店；卡片以活动为维度（见《订单列表 PRD》F0 规则 9），页内活动名称展示为卡片所标注的该活动，其余展示与操作同普通团一致。
  6. 未支付团员订单超时逻辑删除后，门店侧与会员侧均不可进入该团员订单详情，不展示超时提示，见《订单列表 PRD》F0 规则 11。
  7. 订单标识无效时，页面展示「未找到该订单」空状态。

### F2 团员订单处理提示
- **功能描述**：页面根据该团下团员订单的待处理情况，展示对应的操作引导提示（本模块为门店侧操作提示的唯一口径）。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 存在「待支付」团员订单时，提示：「存在未支付团员订单，请在 1 小时内完成支付，超时后系统将自动关闭。」
  2. 不存在「待支付」团员订单、但存在「待核销」团员订单时，按待核销团员订单的可退款情况分别提示（可退款口径见 F5 规则 5）：
     - 存在从未核销（累计已核销份数为 0）的「待核销」团员订单时，提示：「请对下方待核销团员订单进行核销或退款操作。」
     - 全部「待核销」团员订单均已发生部分核销（累计已核销份数大于 0）时，提示：「请对下方待核销团员订单进行核销操作（已部分核销的订单不可退款）。」
  3. 不存在「待支付」和「待核销」的团员订单时，不展示操作提示。

### F3 团员订单明细
- **功能描述**：展示该团聚合下的所有团员订单明细。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 每条团员订单展示：团员订单号、客户姓名、客户手机号、下单时间、金额、状态、推荐门店（仅跨店推荐时展示，口径见 F1 规则 2）、未答复留言标记，以及该订单的服务项目与份数（见 F8）。
  2. 下单时间格式为「MM-DD HH:mm」，每条团员订单展示其独立的创建时间。
  3. 团员订单状态的取值范围见《订单列表 PRD》F0 规则 10。
  4. 由「商家直接分享的订单」卡片进入本页时，卡内团员订单同属一个活动，活动名称在团信息处展示，明细行不重复标注活动（见《订单列表 PRD》F0 规则 9）。
  5. 联系客户：每条团员订单提供「打电话」与「留言」两个入口；「打电话」拨打该订单关联的客户手机号，「留言」进入该订单的留言对话界面（留言规则见 F4）。
  6. 状态相关操作（按团员订单当前状态展示）：
     - 「待支付」：不提供任何手动操作入口，超时由系统自动关闭。
     - 「待核销」：提供「核销」操作（需二次确认，见 F0），核销按服务项目/商品逐份进行，见 F9；从未核销（累计已核销份数为 0）的另提供「退款」操作，已发生部分核销的不再提供退款入口（见 F5 规则 5）。
     - 「已核销」「已退款」：不展示操作入口，仅展示信息。
  7. 若该团员订单存在客户最后留言未被门店答复的情形，「留言」入口展示未答复留言标记（判定见 F4）。

### F4 团员订单留言
- **功能描述**：展示该团员订单的客户留言往来记录，支持门店查看并回复客户留言。本模块为留言保存、展示与未答复留言标记判定的唯一口径，客户与门店共享同一份留言记录。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 留言记录以团员订单为维度保存，每条团员订单拥有独立的留言记录。
  2. 留言按时间正序（从旧到新）展示，最新留言在底部；每条留言标识发送方（客户/门店）及发送时间。
  3. 门店可输入回复内容，发送后追加至留言记录并推送给客户；回复内容为空时不可发送并给出提示。
  4. 未答复留言标记判定（两端各自判定、互不影响）：
     - 门店侧：该团员订单的留言记录中，客户最后一条留言时间晚于门店对该订单的最后一次回复时间时，门店侧「留言」入口展示未答复留言标记。
     - 会员侧：该团员订单的留言记录中，商家最后一条留言时间晚于会员对该订单留言的最后一次查看或回复时间时，会员侧「留言」入口展示未答复留言标记。
  5. 留言记录永久保存，页面默认加载最近 30 条留言。
  6. 未产生任何留言时，展示「暂无留言」。

### F5 退款确认
- **功能描述**：对待核销团员订单发起退款时，弹出退款确认对话框，需店长二次确认（二次确认规则见 F0）。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 退款确认框展示：客户姓名、退款金额（口径见规则 3），以及提示「退款后该团员订单将不可恢复，款项将原路退回至客户支付账户。请确认客户尚未到店核销时发起退款。」
  2. 确认退款后，该团员订单状态变更为「已退款」，款项原路退回。
  3. **退款金额**：为该团员订单金额（全额），不按已核销 / 未核销部分拆分。
  4. 退款完成后，该团员订单不可再执行核销操作。
  5. **退款条件（唯一口径）**：退款仅对「待核销」且从未核销（累计已核销份数为 0）的团员订单可用；已发生部分核销（累计已核销份数大于 0 且未全部核销）、已全部核销（状态为「已核销」）后，均不再提供退款入口。

### F6 技术服务费与门店净收入
- **功能描述**：对团员订单核销时，按规则计算技术服务费与门店净收入。本模块为全项目「技术服务费」「门店净收入」与核销结算流水的唯一口径；核销的份数规则与操作见 F9。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 设单笔核销团员订单的订单金额为 X 元。X ≥ 20 时，技术服务费 = 5 元、门店净收入 = X − 5；X < 20 时，技术服务费 = 0 元、门店净收入 = X。
  2. 技术服务费于该团员订单全部核销完成、状态变更为「已核销」时，从其订单金额中一次性扣除，全部由门店承担，核销后不退还；部分核销阶段（仍为「待核销」）不单独扣费。
  3. 团员订单核销成功后，其净收入才计入【RTB】的结算流水并成为可提现的拓客收入；核销前不入流水、不可提款。
  4. 核销需二次确认：确认框展示内容与执行结果见 F9，二次确认通用规则见 F0。
  5. 团员订单全部份数核销完成、状态变更为「已核销」的核销结果页见《核销成功 PRD》，本模块不重复定义。

### F7 老带新奖励发放
- **功能描述**：当该团所属活动配置了「老带新」玩法、且该团已达成成团时，展示该团奖励发放条件的达成情况，并支持门店在完成线下发放后记录发放结果（线上留痕）。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 仅当该团所属活动配置了「老带新」玩法、且该团已成团时展示本模块；未配置玩法、未成团或由「商家直接分享的订单」卡片进入时不展示。
  2. 奖励发放对象为该团的分享人；本模块仅记录门店线下发放的结果，页面不执行奖励的实际发放，也不改变奖励内容与金额。
  3. 页面展示发放条件的达成情况：达成成团条件时提示「已达成发放条件」；奖励发放需二次确认（见 F0）：门店点击「确认发放奖励」并确认后，发放状态记录为「已发放」，会员侧同步展示为已发放。发放状态仅区分「未发放/已发放」，确认后不可重复、不可撤销；页面不展示奖励的具体内容。
  4. 会员侧「已发放」的展示形态见《活动详情 PRD》F6 规则 11。
  5. 成团判定、奖励内容、奖励发放与有效期规则见《活动详情 PRD》F6，本模块不展开。

### F8 团员订单服务项目与份数
- **功能描述**：每条团员订单明细逐项展示该笔订单包含的服务项目/商品及其份数，并逐项展示核销进度，用于核对门店履约内容。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 每条团员订单以其包含的服务项目/商品**逐项各占一行**展示（弱化样式），每行展示项目/商品名称与份数（如「深层补水焕活 ×2」），并逐项展示该项核销进度。
  2. 服务项目/商品与份数取该笔团员订单创建时的快照，逐单展示。同一活动下不同团员订单的项目与份数可能不同（活动经门店编辑后，后续订单按编辑后的内容生成）。
  3. 逐项核销进度展示：「待核销」订单展示「已核销 X/Y 份 · 剩余 Z 份」（X 为该单项累计已核销份数、Y 为该单项份数）；「已核销」订单展示「已核销 Y/Y 份」；「待支付」「已退款」订单仅展示份数（「×Y」）。已核销份数口径见 F9。
  4. 服务项目/商品与份数仅作履约内容展示；该笔订单金额见 F1、F3，金额口径见《订单列表 PRD》F0 规则 8。

### F9 逐份核销
- **功能描述**：对待核销团员订单按服务项目/商品逐份核销，支持分次核销。本模块为「核销份数」与团员订单核销状态判定的唯一口径。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 核销入口仅对「待核销」状态的团员订单展示（见 F3 规则 6）；「待支付」「已核销」「已退款」的团员订单不可核销。
  2. 核销时按服务项目/商品逐项选择本次核销的份数：每项可选范围为 0 至该项剩余未核销份数，可跨多个项目同时选择，各项累计须大于 0 份。
  3. 每项的剩余未核销份数 = 该项的份数 − 该项累计已核销份数；已核销份数以团员订单为维度累计保存。
  4. 核销需二次确认（见 F0）：确认框展示客户姓名、本次核销份数，并提示「请确认客户已到店」；取消则不做任何改动。
  5. 确认核销后按本次选择份数累加各项已核销份数：
     - 该团员订单全部服务项目/商品份数核销完成时，团员订单状态变更为「已核销」，并进入核销成功页（见《核销成功 PRD》）。
     - 未全部核销时，团员订单状态保持「待核销」，剩余份数可再次核销；本次核销完成后停留在本页并给出剩余份数提示。
  6. 「待核销」是未全部核销团员订单的统一状态，含从未核销与部分核销两种情形，状态口径同《订单列表 PRD》F0 规则 10；部分核销后的退款口径见 F5 规则 5，技术服务费扣费时点见 F6 规则 2。
