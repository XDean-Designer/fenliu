# [订单详情（会员侧）] PRD

## 一、User Story
> 作为平台会员，我希望通过支付短信链接或订单列表进入订单详情页，查看订单金额、状态、服务内容、订单信息及商家信息，以便了解订单情况并完成支付或处理售后。

## 二、Function Requirements

### F1 订单金额与状态
- **功能描述**：展示订单金额、订单状态及对应说明。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 订单金额为订单创建时按活动售价计算的金额（计算规则见《活动配置 PRD》F5 及本文件 F5）。
  2. 订单状态包括待支付、已支付、已使用、已退单四种，与门店侧团员订单状态的对应关系见《订单列表 PRD》F0 规则 10。
  3. 各状态说明文案：
     - 待支付：「请在 1 小时内完成支付，超时订单将自动取消并关闭」（有效期见《订单列表 PRD》F0 规则 11）。
     - 已支付：「支付成功，到店请向商家报下单手机号即可使用」（会员到店使用方式口径见《活动详情 PRD》F5）。
     - 已使用：「服务已使用完成，感谢您的惠顾」。
     - 已退单：「订单已退单，如有疑问请联系商家」。
  4. 订单不展示分享/成团相关信息（相关规则见《活动详情 PRD》F6）。

### F2 服务内容
- **功能描述**：展示订单包含的活动下的全部项目（服务项目与商品），并按「项目 × 数量」标注每个项目的使用情况。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 标题展示订单包含的项目数量及总份数（如「4 个项目 · 共 5 份」）；已支付、已使用订单在末尾追加「已使用 x 份」（x 为各项目已使用份数之和，只保留已使用份数、不展示总份数；已使用份数为 0 时同样追加「已使用 0 份」），与《我的订单 PRD》F3 口径一致；待支付、已退单订单不追加。
  2. 每个项目展示名称、类型（服务项目/商品）、售价及数量（如「×2」），并标注该项目使用情况。
  3. 使用情况标签按该项目已使用份数取值，统一去分母、只保留已使用份数：
     - 已使用份数为 0：展示「未使用」。
     - 已使用份数大于 0：展示「已使用 X 份」（X 为已使用份数）；部分使用与全部使用共用该文案，不再展示总份数。
  4. 使用情况按各项目实际已使用份数展示，口径统一、不因订单状态做特殊处理：待支付、已退单订单未产生使用记录，各项目均展示「未使用」；已支付、已使用订单均按各项目实际已使用份数展示。会员侧「已使用」对应门店侧「已核销」，已使用份数口径见《订单详情（门店侧）PRD》F9。
  5. 项目类型区分「服务项目」「商品」；活动下项目的可配置范围（分类）见《创建活动 PRD》F2 规则 1。

### F3 商家信息
- **功能描述**：展示订单所属商家的名称及地址。
- **数据来源**：数据来源于【RTB】。

### F4 订单信息
- **功能描述**：展示订单编号、活动名称、下单时间及订单状态。
- **数据来源**：数据来源于【RTB】。

### F5 金额明细
- **功能描述**：展示订单的活动原价、优客圈优惠及订单金额。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 活动原价为活动内所有项目原价之和（计算规则见《活动配置 PRD》F5）。
  2. 优客圈优惠为活动原价与活动售价之差。
  3. 订单金额为活动内所有项目售价之和，等于活动原价减去优客圈优惠。

### F6 底部操作栏
- **功能描述**：页面底部提供「联系商家」「留言」及「立即支付」操作入口。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 「联系商家」用于会员直接拨打商家联系电话。
  2. 「留言」用于会员与商家进行文字沟通；C 端一笔订单对应门店侧一笔团员订单，双方共享同一份留言记录，留言规则见《订单详情（门店侧）PRD》F4。
  3. 当商家最后一条留言未被会员查看或回复时，留言入口展示未答复留言标记（判定标准见《订单详情（门店侧）PRD》F4）。
  4. 「立即支付」仅在订单状态为待支付时展示；支付成功后订单状态更新为已支付。
  5. 未产生任何留言时，展示「暂无留言，您可以给商家留言」。

### F7 返回逻辑
- **功能描述**：页面返回按钮统一返回我的订单列表页。
- **数据来源**：数据来源于【RTB】。
