# [活动详情] PRD

## 一、User Story
> 作为收到商家短信或好友分享链接的会员，我希望打开活动详情页，查看活动价格、服务内容、活动信息、老带新玩法、商家信息及消费须知，以便了解活动并完成下单支付，或分享邀请好友参团。

## 二、Function Requirements

### F1 活动头图
- **功能描述**：页面顶部展示活动的多张轮播头图，头图直接顶到页面顶部，无顶部导航栏。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 头图展示活动主视觉，可多张轮播。
  2. 图片取活动项目的图片进行轮播，有多少取多少；服务项目缺图时按 F10 自动生成，商品以自有图片展示（见 F10 规则 5）。
  3. 活动下架后头图照常展示，不置灰、不留空。

### F2 价格信息条
- **功能描述**：展示活动的当前售价与原价。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 活动售价与活动原价的计算规则见《活动配置 PRD》F5。
  2. 活动下架后售价与原价照常展示，供会员回顾活动内容。

### F3 商家信息
- **功能描述**：展示活动所属商家的名称、地址、营业时间及「联系商家」入口。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 展示商家名称、商家地址及营业时间。
  2. 展示「联系商家」入口，会员点击后直接拨打商家联系电话。

### F4 服务内容
- **功能描述**：展示活动包含的项目清单（服务项目与商品）。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 展示活动包含的项目数量及总份数。
  2. 每个项目展示名称、类型（服务项目/商品）、售价、原价及份数（售价计算规则见《活动配置 PRD》F5）。

### F5 活动信息
- **功能描述**：展示活动的标签、使用方式及活动说明。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 展示活动标签、使用方式（到店报手机号使用）及活动说明。
  2. 使用方式为到店消费，会员到店后向商家报下单手机号即可使用。本规则为会员消费使用方式的唯一口径，与老带新奖励发放（见 F6）相互独立；c019 F7 消费须知与《订单详情（会员侧）PRD》F1 的对应文案引用本口径，不复述。

### F6 老带新 · 我的团
- **功能描述**：当活动配置了「老带新」玩法时，展示分享者奖励、成团门槛、本人分享团的成团进度与状态、奖励有效期说明与分享归因提醒，及「分享邀请好友参团」入口。本模块为老带新玩法在全项目的唯一口径。老带新为在优客圈（异业推荐）基座之上的分享聚合玩法。
- **数据来源**：成团门槛订单笔数、分享者奖励来源于【RTB】（B 端在活动配置中选择「老带新」时补充，配置规则见《活动配置 PRD》F4）；本人分享团已参团订单笔数、订单归属来源于【RTB】；奖励发放状态来源于【RTB】（门店侧记录，见《订单详情（门店侧）PRD》F7）。
- **业务规则**：
  1. 仅当活动配置了「老带新」玩法时展示本模块，未配置则不展示。
  2. 展示分享者奖励（即 B 端填写的达成奖励）与成团门槛（即成团所需订单笔数，如「满 3 笔成团」）。
  3. 成团门槛按归入本人分享团的订单笔数计：被分享订单与分享人本人的自购订单均计入，未归因订单不计入；订单归属规则见《订单列表 PRD》F0 规则 4、规则 5。
  4. 展示本人分享团的成团进度，即已参团订单笔数与成团门槛的对比。已参团订单笔数 = 归入本人分享团的订单笔数（含被分享订单与本人自购订单），同一被分享人或本人的多笔订单累计计入；分享人本人可不下单，未下单时仍展示其分享团的进度；成团进度可超过成团门槛。
  5. 计入与刷新时点：订单支付完成即计入成团进度（被分享订单与本人自购订单同口径）；会员每次进入活动详情页时实时获取最新进度，不做本地保存。
  6. 成团判定：已参团订单笔数达到成团门槛即判定成团，展示「已成团 · 奖励可到店领取」；未达门槛时展示「还差 N 笔成团」。已计入进度的订单后续发生退款，不扣减进度，成团进度只增不减；已成团状态不因退款回退。本规则为成团进度与退款关系的唯一口径。
  7. 奖励发放：奖励仅发放给分享人，被分享人不参与奖励；成团后由门店完成线下发放并在线上记录「已发放」，会员侧同步展示为已发放（见《订单详情（门店侧）PRD》F7）。奖励自活动上线起一直有效，直至活动下架；活动下架后未发放的自动失效，页面同步展示该有效期说明。
  8. 提供「分享邀请好友参团」入口，用于生成并分享本活动的分享链接；分享链接携带分享人归因标识，是订单归因的唯一凭证（见《订单列表 PRD》F0 规则 4）。页面内分享按钮与微信小程序原生转发同为有效分享渠道，均携带归因标识并产生订单归因；无法携带归因标识的分享渠道，其产生的订单按无归因渠道处理（见《订单列表 PRD》F0 规则 4）。本规则为分享渠道归因的唯一口径。页面在成团进度下方展示分享归因提醒「只有通过下方分享按钮分享后才能计入你的团哟」，提示会员归因的有效渠道。
  9. C 端为单视角展示：页面始终以「我的团」呈现当前会员作为分享人的成团进度，不因访问者身份（分享人或被分享人）切换展示内容；分享链接所携带的归因标识仅用于订单归因，不在页面展示。
  10. 成团进度与成团状态仅在活动详情页展示；C 端订单页不展示成团信息（见《订单详情（会员侧）PRD》F1、《我的订单 PRD》F3）；B 端订单详情页仅提供奖励发放的线下留痕入口（见《订单详情（门店侧）PRD》F7）。
  11. **奖励已发放后的展示**：分享人的奖励在门店侧记录为「已发放」后，本卡片不再展示分享者奖励、成团门槛、成团进度、奖励有效期说明与分享归因提醒，也不再提供「分享邀请好友参团」入口，仅展示「奖励已发放，如有问题可以联系商家确认。」。发放状态仅区分「未发放/已发放」，确认后不可重复、不可撤销（见《订单详情（门店侧）PRD》F7）。

### F7 消费须知
- **功能描述**：展示面向会员的消费规则说明。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 本活动为优客圈会员专享价，下单后需到店消费。
  2. 会员到店的消费使用方式引用 F5 规则 2 的口径，本模块不复述。
  3. 如需预约，会员需提前联系商家确认到店时间。
  4. 如对服务有疑问，会员可联系商家或平台客服咨询。

### F8 底部购买栏
- **功能描述**：页面底部展示活动价及下单入口。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 展示活动售价（计算规则见《活动配置 PRD》F5）。
  2. 活动上架期间，会员点击「立即下单」直接生成一条待支付订单（固定生成 1 条订单，各项目份数按活动配置，不提供份数选择与二次确认），并进入订单详情页完成支付；支付规则见《订单详情（会员侧）PRD》F6。
  3. 活动上架期间正常售卖，活动所包含的项目（含服务项目与商品）自身失效不影响下单与使用（项目快照规则见《活动配置 PRD》F8）。
  4. **活动下架后不可下单**：活动下架后，会员仍可打开活动详情页并正常浏览活动价格、服务内容、活动信息、商家信息与消费须知；该活动不再售卖，底部下单入口置为不可下单状态并展示「活动已结束」，会员点击后提示「活动已结束」，不生成订单。活动上/下架规则见《联盟广场 PRD》F4。

### F9 悬浮订单入口
- **功能描述**：页面右下角展示悬浮的「我的订单」圆形按钮，并显示本人订单数量角标。
- **数据来源**：数据来源于【RTB】。
- **业务规则**：
  1. 悬浮按钮展示「我的订单」入口，角标展示当前会员本人的订单数量（含全部订单状态）。
  2. 进入后展示当前会员本人的全部订单。

### F10 活动图片智能生成
- **功能描述**：当活动包含的服务项目图片缺失时，系统自动生成与该项目相匹配的活动图片，用于活动版面展示。
- **数据来源**：缺失图片的服务项目名称、分类来源于【RTB】；生成的活动图片回写至【RTB】作为活动图片使用。
- **业务规则**：
  1. 服务项目缺少图片时，系统自动触发图片生成，生成与项目匹配的活动图片，用于活动头图及服务项目展示。
  2. 图片生成存在延迟；生成完成前，头图与服务项目展示位以占位图/默认图兜底，不留空白。
  3. 生成图片比例为 1:1；活动头图与活动卡片统一按 1:1 展示规范适配手机端。
  4. 图片生成所用提示词由「通用风格」与「项目名称+项目分类」两部分自动组装，模板见下方。
  5. 本功能仅针对服务项目：仅服务项目缺图时自动生成图片；商品不触发图片生成。商品图片缺失时的展示处理：以商品自有图片展示，缺失时以默认占位图兜底。

### 活动图片生成提示词（移交开发使用）

**通用风格（固定前缀，每次生成均携带）**
> 生成一张高端美业门店的活动宣传图，传递"专业、品质、安心、焕然一新"的氛围。画面干净通透、留白充足，色彩柔和高级，主体突出，适配手机端电商活动卡片/头图（比例 1:1）。请勿生成文字、水印、品牌 Logo、夸张特效或低俗画面。人物置于自然的景中，展现服务状态而非面部特写。整体风格为现代轻奢美业视觉。
